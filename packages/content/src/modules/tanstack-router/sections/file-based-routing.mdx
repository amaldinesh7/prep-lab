<SectionHeader kind="concept" number={2} title="File-based routing" />

The filesystem is the route config. You add a file under `src/routes/`, the plugin watches it, and a generated file (`src/routeTree.gen.ts`) wires it into a typed router. No central array of `{ path, element }` to maintain.

## Setup — the Vite plugin

Two installs and one plugin entry. Plugin order matters: `tanstackRouter` must run before `react`.

<Code lang="ts" file="vite.config.ts">{`import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import { tanstackRouter } from "@tanstack/router-plugin/vite";

export default defineConfig({
  plugins: [
    // Order matters: router plugin first, then React.
    tanstackRouter({
      target: "react",
      autoCodeSplitting: true,
      // Defaults shown for clarity:
      routesDirectory: "src/routes",
      generatedRouteTree: "src/routeTree.gen.ts",
    }),
    react(),
  ],
});`}</Code>

`autoCodeSplitting: true` is the option you want on for any non-trivial app. It splits every route component into its own chunk and lazy-loads on navigation. We come back to this in the gotchas section.

## Filename to URL mapping

The plugin has one job: parse filenames into a route tree. The conventions are tight.

<Cheatsheet rows={[
  { k: "src/routes/index.tsx", v: "/" },
  { k: "src/routes/about.tsx", v: "/about" },
  { k: "src/routes/posts.index.tsx", v: "/posts" },
  { k: "src/routes/posts.$postId.tsx", v: "/posts/:postId (param)" },
  { k: "src/routes/posts.$postId.edit.tsx", v: "/posts/:postId/edit" },
  { k: "src/routes/__root.tsx", v: "Layout wrapping every route" },
  { k: "src/routes/_authed.tsx", v: "Pathless layout (groups without URL segment)" },
  { k: "src/routes/_authed.dashboard.tsx", v: "/dashboard, inside _authed layout" },
  { k: "src/routes/files.$.tsx", v: "Catch-all / splat route" },
]} />

Two characters carry meaning:

- **`.` (dot)** in a filename creates a URL segment boundary. `posts.$postId.tsx` is `/posts/$postId`. You can also use folders — `posts/$postId.tsx` is identical. Pick a convention and stick with it; a team that mixes both will regret it.
- **`_` (underscore prefix)** is a _pathless layout route_. It groups children without adding a URL segment. Use it for authenticated areas, marketing layouts, or anywhere children share UI but not a URL prefix.

`__root.tsx` (two underscores) is special. It's the outermost layout, always rendered, and the only file that uses `createRootRoute` (or `createRootRouteWithContext`).

## A real folder, end to end

<Code lang="tsx" file="src/routes/__root.tsx">{`import { createRootRoute, Link, Outlet } from "@tanstack/react-router";

export const Route = createRootRoute({
  component: RootLayout,
});

function RootLayout() {
  return (
    <div className="app">
      <nav>
        <Link to="/">Home</Link>
        <Link to="/posts">Posts</Link>
      </nav>
      <main>
        <Outlet />
      </main>
    </div>
  );
}`}</Code>

<Code lang="tsx" file="src/routes/posts.$postId.tsx">{`import { createFileRoute } from "@tanstack/react-router";

export const Route = createFileRoute("/posts/$postId")({
  component: PostDetail,
  loader: async ({ params }) => {
    // params.postId is typed as string — no annotation needed.
    const res = await fetch(\`https://jsonplaceholder.typicode.com/posts/\${params.postId}\`);
    if (!res.ok) throw new Error("not found");
    return (await res.json()) as { id: number; title: string; body: string };
  },
});

function PostDetail() {
  const post = Route.useLoaderData();   // typed from the loader return
  const { postId } = Route.useParams(); // typed { postId: string }
  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.body}</p>
      <small>id: {postId}</small>
    </article>
  );
}`}</Code>

Three details to internalize from that file:

1. `createFileRoute("/posts/$postId")` — the string literal _must_ match the filename's URL. The plugin will overwrite it if you get it wrong, but get in the habit of typing it correctly so PR reviews don't fight the codegen.
2. `Route` is the local export. You import it _from this file_ in this file — you read params and loader data off the route object, not via global hooks. That's how TSR keeps inference per-route precise.
3. The component is a plain function. No HOC, no provider plumbing. The framework is invisible until you ask for typed data.

## The generated route tree

After Vite starts, you get `src/routeTree.gen.ts` — a few thousand lines of generated TypeScript that:

- Imports every route file
- Builds the typed route tree (a giant typed object that TS uses to resolve `<Link to="...">` autocompletes)
- Exports `routeTree`, which you hand to `createRouter`

<Code lang="tsx" file="src/main.tsx">{`import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { createRouter, RouterProvider } from "@tanstack/react-router";
import { routeTree } from "./routeTree.gen";

const router = createRouter({ routeTree });

// Augment the global Register so <Link>, useNavigate, etc. know your tree.
declare module "@tanstack/react-router" {
  interface Register {
    router: typeof router;
  }
}

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <RouterProvider router={router} />
  </StrictMode>,
);`}</Code>

The `declare module` block is non-optional in any real app. Without it, `<Link to="/posts/$postId">` won't autocomplete and won't be type-checked. Adding it once gives you typed routing everywhere — every `<Link>`, every `useNavigate`, every `<Navigate to>`.

<Callout kind="pattern">
  Commit `routeTree.gen.ts` to source control. It's generated, but it's also the contract every other file depends on for types. Skipping it from git means fresh clones fail typecheck until the dev server has run once. Treat it like a lockfile.
</Callout>

## What about the `code: route` API?

TSR supports a code-based route API (`createRoute` without files) for people who hate magic. You can mix both. Don't. Pick file-based for new apps — the team velocity from "URL = file path" is the entire point. Code-based is an escape hatch for dynamic routes generated at runtime (rare).
